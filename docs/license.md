# Licensing status

The source repositories are publicly readable. A public repository and an explicit open-source license are different things.

Earlier GitBook text described MIT licensing for reference software published with that license. At the [reviewed revisions](README.md), neither application's repository includes a project-level `LICENSE` file. This documentation update does not invent a license grant for the entire project or retroactively apply one to all files.

Until the maintainers publish that file and its scope, do not assume that the whole codebase, documentation, artwork or branding has an MIT grant solely because this website is public. The missing license is tracked in [open gaps](roadmap.md).

Third-party components retain their own notices. The marketplace includes an [ethers license notice](https://github.com/deadpixelslabs/ZEC-BLOCKS/blob/95648a4d7948dfb8c2466ed941718f405827621c/vendor/ETHERS-LICENSE.txt); that notice does not license unrelated project files.

An explicit project license should identify covered software, attribution requirements and any separate treatment of documentation and assets. Names, logos and trademarks should not be treated as granted merely by a software license statement.

The goal is a clear, verifiable permission record alongside the code, rather than an unsupported “open source” badge.
